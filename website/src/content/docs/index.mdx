Harbor is a cross-platform, language-agnostic application hosting platform.
It replaces the combination of IIS + ARR + NSSM (or nginx + systemd/PM2 on
Linux) with a single daemon, CLI, and — eventually — GUI: point it at a
Python, Node.js, .NET, Java, or Rust project and it handles process
supervision, restart policy, log capture, and reverse-proxied HTTPS through
one consistent command surface, on Windows, macOS, or Linux alike.

This site documents **Phases 1–3**: process supervision, a reverse proxy
with TLS/ACME and config hot-reload, and native OS service registration.
The GUI is the remaining later phase — see
[Roadmap & Status](/harbor/roadmap/) for exactly what's implemented today
versus what's planned.

## What Harbor does today

<CardGrid>
	<Card title="Process supervision" icon="rocket">
		Point Harbor at a project directory. It auto-detects the runtime,
		launches it, captures logs, and restarts it per a configurable policy —
		start, stop, restart, and status from one CLI.
	</Card>
	<Card title="Cross-platform" icon="laptop">
		The same daemon, CLI, and TOML config format on Windows, macOS, and
		Linux. No more OS-specific tooling per machine.
	</Card>
	<Card title="Declarative config" icon="document">
		Every app is a plain, version-controllable TOML file. No hidden binary
		state to lose track of.
	</Card>
	<Card title="Auto-recovery" icon="setting">
		Apps come back after a daemon restart — and a live orphan left behind by
		an unclean shutdown is detected and reaped before its replacement
		spawns.
	</Card>
	<Card title="Reverse proxy + HTTPS" icon="approve-check">
		Route by domain or URL path to an app's port, with WebSocket
		passthrough. HTTPS works immediately via an auto-generated self-signed
		certificate, upgraded transparently to a real one if you enable ACME.
	</Card>
	<Card title="Hot-reload" icon="magnifier">
		The daemon watches your app configs and applies changes automatically —
		or trigger it explicitly with `harbor apply`.
	</Card>
	<Card title="Native OS service" icon="server">
		`harbor service install` registers the daemon with systemd, launchd, or
		a real Windows Service, so it starts at boot without a terminal left
		open.
	</Card>
</CardGrid>
